# Release v1.2.0

## Changes
- Added DHW quota exclusive duty-cycling: when domestic hot water is the only
  reason the pump runs (no room heating demand), quota runs are now capped at a
  configurable max duration and separated by a configurable pause, spreading
  water heating evenly across the day instead of one continuous morning block.
- New helpers:
  - `input_number.dhw_exclusive_max_run_min` — max continuous DHW-only run
    (default 45 min, 0 disables duty-cycling)
  - `input_number.dhw_exclusive_pause_min` — pause between DHW-only runs
    (default 90 min, 0 disables duty-cycling)

## Behavior
- Room-demand pump starts are never delayed by the DHW pause.
- `min_pump_on` / `min_pump_off` compressor-protection timers always take
  precedence over the new limits.
- Setting either helper to 0 restores the previous continuous-run behavior.

## Fixes
- A manual TRV setpoint change while the FSM is in steady `OFF` or
  `OFF_LOCKOUT` no longer lingers on the thermostat until the next state
  transition: the room is re-parked at the off setpoint within one tick
  (the change is still remembered in `user_sp` and heats once demand
  appears).
- Every recorded user setpoint change now logs its demand evaluation
  (`t_cur` vs the hysteresis threshold), including an explicit warning
  when `current_temperature` is unavailable — previously that case
  silently produced "no demand".

- Steady-`OFF` re-parking no longer commands a TRV whose setpoint is
  unavailable (offline device) nor a room marked unmanaged after failed
  commands; without this, one offline TRV meant a `climate.set_temperature`
  call every minute all day. The room is re-parked on the first tick after
  it comes back.
- The Sonoff relay can still read `on` for one tick after
  `script.wylacz_pompe` (seen in production logs). That tick no longer
  re-enters `DHW_QUOTA`/`HEAT_*` (which reset `state_since`) and no longer
  re-fires the stop script or re-stamps `last_pump_off`; the tick is logged
  as `[PUMP] stop pending` (`PUMP_STOP_SETTLE_MIN`, 3 min).

## Tests
- Added `tests/test_heat_orchestrator_sim.py`: a pytest simulation with a
  stubbed `hassapi` and configurable relay lag covering the duty cycle,
  re-parking and the relay-lag cases above (`python -m pytest tests`).

## Codebase
- Repository synced with the deployed orchestrator: `Room` config class,
  `garaz` room, renamed FF rooms (`pokoj_narozny`, `pokoj_z_garazem`),
  pump controlled via `script.uruchom_pompe` / `script.wylacz_pompe`
  with the Sonoff relay as authoritative state, power-meter pump health
  cross-check (`input_text.pump_health`).

## Upgrade Notes
- Add the two new helpers (via the updated
  `packages/heat_orchestrator_helpers.yaml` package or manually) and restart
  Home Assistant, then reload AppDaemon. Without the helpers the app falls back
  to the built-in defaults (45/90 min).
